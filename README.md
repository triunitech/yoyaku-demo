# 予約管理デモ（小規模店舗向け）

> **TRIUNITECH が自社で制作したデモです。受託案件ではありません。**
> 画面上のデータはすべて架空のもので、お使いのブラウザ内にのみ保存されます。

美容室・整体院・教室など、スタッフ数名の店舗を想定した予約管理アプリです。
「既存業務に合わせた小規模な Web システムを、どのような品質・進め方でお作りするか」を
ご確認いただくための見本として公開しております。

- デモ：（公開後に URL を記載）
- 技術：Next.js 15（App Router、静的エクスポート）／ React 19 ／ JavaScript
- 外部ライブラリ：なし（Next.js・React のみ）

## 主な機能

| 機能 | 内容 |
|---|---|
| 週間カレンダー | スタッフ別に色分けして表示。空き枠をクリックして予約登録 |
| 予約の登録・変更 | 日付・時刻・メニュー・担当・お客様情報。状態（予約／来店済／キャンセル）の管理 |
| 入力チェック | 同じ担当者の時間の重なり、定休日、営業時間外、過去日、電話番号の形式 |
| 予約一覧 | 期間・状態での絞り込み、キーワード検索、CSV 出力（Excel で文字化けしない BOM 付き） |
| メニュー管理 | 追加・編集・削除。今後の予約で使用中のメニューは削除不可 |
| 店舗設定 | 店舗名、営業時間、定休日 |

## 設計上の考え方

- **業務ロジックと画面の分離**：予約の重複判定や入力チェックは `lib/booking.js` に集約し、画面（`components/`）から独立させています。
- **テスト**：業務ロジックは Node.js 標準のテストランナーで単体テストしています（`tests/booking.test.js`、追加パッケージ不要）。
- **本番化を想定した構成**：保存処理は `lib/store.js` のみに閉じています。本番導入時はここを API 呼び出しに置き換えることで、画面をそのまま使えます。
- **履歴の保持**：メニューの料金や名称を変更しても、登録済みの予約は予約時点の内容を保持します。

## 動かし方

```bash
npm install
npm run dev     # 開発サーバー http://localhost:3000
npm test        # 単体テスト
npm run build   # 静的ファイルを out/ に出力
```

## ディレクトリ構成

```
app/          画面のエントリーポイント・共通スタイル
components/   画面部品（カレンダー、予約フォーム、一覧、メニュー、設定）
lib/          業務ロジック（date.js / booking.js）と保存処理（store.js）
tests/        単体テスト
```

## 本番導入時に追加を想定している機能

予約確認・前日リマインドメール、複数店舗対応、監査ログ。
